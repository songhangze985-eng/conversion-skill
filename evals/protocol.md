# A/B/C 对照评测协议

用于比较「不装 Skill」「只给详细讲解提示词」「使用 conversion-skill」。本文件是执行规范，不是实验结果。

## 固定条件

三组必须共用：

- 同一模型名称与版本
- 同一条测试输入（`evals/inputs/` 原文，不改写）
- 同一采样设置（温度、top_p、最大输出长度）；若宿主不能锁定，把实际设置写进记录
- 同一评分人 / 同一评分模型，以及 `rubric.md` 的四维量表
- 同一输出语言（默认中文）

不要为了让 C 组更好看而给它更短的输入、更低的温度，或更松的量表。

## 三组

### A 组：原生模型

只发送 `evals/prompts/group-a.md` 加上对应 `inputs/Cxx-*.md`。不粘贴 SKILL.md，不安装 conversion-skill。

### B 组：详细讲解提示词

发送 `evals/prompts/group-b.md` 加上同一输入。这是「认真讲人话」的对照，不是本 Skill 的精简版。不要要求映射表、知识点校验或风格元数据。

### C 组：conversion-skill

在已安装本 Skill 的宿主中发送同一输入。允许宿主按 description 自动触发；若必须显式点名，在记录里写明。不要把 SKILL.md 全文再贴进用户消息。

## 每条记录必须写下

按 `record-template.md` 填写：

- 测试输入（文件名与原文）
- 模型与运行配置
- A/B/C 三组原始输出（或「未执行」）
- 事实错误与遗漏
- `check-output` 的结构检查、术语/ID 覆盖结果
- 四维质量评分与依据
- 执行耗时与输出长度
- 失败原因

A、B 两组通常没有映射表。对它们跑 `check-output` 时，结构检查失败是预期现象，只能记作「结构不适用 / 机械 FAIL」，不能记作语义 0 分。语义分仍按 `rubric.md` 看正文。

## 题目规模

`cases.md` 提供不少于 12 道知识题，覆盖算法、数学、分布式、网络协议和论文核心机制；另有边界题，不强制做 A/B/C。优先复用仓库已有样例，再补公共知识题。不要加入私有论文全文。

## 什么时候可以写结论

只有在同一配置下收齐某题的 A/B/C 原文，并完成四维评分后，才能比较该题。缺一组就写「未完成」，不要用主观印象补分。

不得把结构 PASS、关键词覆盖或理解检验出题数写成「理解能力提升」。
