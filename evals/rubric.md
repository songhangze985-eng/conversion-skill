# 评分量表

四维各 0–2 分，标准不因项目想拿高分而放宽。

普通对照评测：总分 ≥6，且「能懂」「保真」都 ≥1，才算过线。本地论文验收只有**四维全为 2、总分严格 8/8** 才算 PASS。6/8、7/8 或结构门禁失败都必须报告失败项，不能用总分平均掩盖。

结构检查、术语出现和事实 ID 覆盖是另一件事。它们不能提高本量表的分数，也不能代替本量表。

## 1. 能懂

- **2**：领域外读者能用一句大白话说明它在干什么、有什么边界；必要术语第一次出现已用动作解释。
- **1**：主旨正确，仍有一两处需停下来问。
- **0**：读完仍需回原文，或只把术语换成另一组术语。

## 2. 保真

- **2**：正文与知识点校验完整保留事实清单中的核心机制、顺序和约束；无无依据的因果、数据、结论或机制反转。
- **1**：主干正确，但遗漏一条会影响边界理解的约束或关系。
- **0**：机制、条件、方向或结论讲反，或以虚构情节替代原机制。

## 3. 机制同构

- **2**：映射表可按步骤逐一对照，输入、动作、输出与约束都有明确落点；一个元素不承载多个无关概念。
- **1**：大部分对得上，但有一处只有表面相似、没有行为对应。
- **0**：缺少合格映射表，或主要映射明显错配。

## 4. 表达不挡懂

- **2**：所选表达方式增强记忆或观察，不增加术语负担；风格词删掉后机制仍可复述。
- **1**：略吵或略泛化，尚不妨碍理解。
- **0**：角色口癖、侦探黑话、岗位缩写、景物堆砌或情况回复压过知识；或为了风格扭曲机制。

## 结构门禁（任一失败即不通过）

- 标题下有 `> 表达风格：\`<anime|detective|war-room|nature-documentary|neutral>\`` 与 `> 篇幅：\`<default|expand|long>\``。
- 映射表含「知识概念｜故事元素｜对应理由」三列、分隔行和至少一条非空映射。
- 正文后有含「知识点校验」的 Markdown 标题与非空校验内容。
- `default` 档正文不超过 800 汉字；`expand` 与 `long` 按本技能篇幅规则处理。
- `author-voice.md` 的固定情况句不出现在正文或知识点校验中。
- 本地检查运行 `bun run check-output -- <result.md> --level <level> --style <style> [--facts <absolute-temp/fact-ledger.verified.json>]`。这里的 PASS 只覆盖结构检查与事实术语/ID 覆盖；语义质量和用户理解必须按上面四维另行复核。

## 论文严格验收附加条件

- 只使用本次用户指定的论文作为验收语料；论文、抽取文本、页图、事实清单、转换稿和评分卡只存在于仓库外的绝对临时目录。
- 用于评分的事实清单必须是人工或模型复核过的 `fact-ledger.verified.json`，不可用抽取器自动生成的 draft 冒充。
- 清单内每个 `required_terms` 必须出现在正文或知识点校验；每个 `mapping_terms` 必须出现在映射表第一列；每个事实 ID（如 `[F1]`）必须同时出现在映射表与知识点校验。覆盖率必须 100%。
- 运行时只把 PDF 提取、关键页渲染和结构校验计入每篇 60 秒的工具预算；正文生成耗时单独记录，不混入工具性能结论。
- 发现页图与抽取文本冲突、事实无法证实，或任一维不为 2 时停止宣称满分，转为报告缺口或失败原因。
