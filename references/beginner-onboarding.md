# 小白与低理解力友好指南（`beginner-onboarding`）

本文件专门针对**零基础小白、跨行初学者或自述理解能力偏弱**的用户。当用户提问中带有「我是纯小白」「理解能力差」「完全看不懂」「像看天书」「用最笨的大白话讲」或追问「还是没太懂」时，读取本文件并启用**超低认知负荷模式**。

---

## 一、让小白「上手并爱上」的五级体验标准

### 1. 开口零门槛（不考用户怎么提问）

小白最怕「连问题都不会问」。无论用户只丢过来一个干巴巴的词（如「死锁」）、一段看不懂的报错，还是带着情绪吐槽「这到底是个啥玩意儿」，直接接住并替他把痛点翻译成日常麻烦，不要反问他「你想了解哪个技术维度」。

### 2. 情绪零羞辱（严禁居高临下词）

理解力吃力的读者对「智力贬损」极其敏感。一旦没看懂却读到「其实很简单」「显而易见」「不难发现」，会立刻产生挫败感并关掉页面。

- **全文铁律**：禁用 `其实很简单`、`显而易见`、`不难理解`、`不难发现`、`稍有常识`、`顾名思义`、`不言自明`。
- **替代姿态**：直接承认这个概念平时之所以难懂，是因为教材省掉了前面的麻烦，然后带着读者一起踩一遍那个麻烦。

### 3. 开篇前三秒踩中日常吃亏经验（前 45 字零黑话）

不要在第一段前两句里抛出任何英文缩写、公式或学术名词。

- **正确切入**：直接从每个人都有体感的吃亏经验切入（做菜咸了、超市排队被卡住、寄快递忘写门牌号、群聊两个人同时抢话、抽屉卡死拉不开）。
- **体感词优先**：多用看得见摸得着的器物与动作（如 `手`、`眼`、`拿`、`放`、`排队`、`桌`、`锁`、`本子`、`账单`、`锅`、`印章`），让大脑直接调取画面。

### 4. 工作记忆防爆仓（一次只拐一个弯）

理解能力弱的本质原因往往是**单次工作记忆（Working Memory）容量装不下多重嵌套**。

- **小句均长控制在 18 字以内**：每句话只交代一个动作或一个结果，绝不把三个前提条件塞进同一个长分句。
- **砍掉次要分支**：第一遍只讲主干是怎么跑通的；边缘异常和复杂特例留到读者点名追问时再展开。

### 5. 一秒带走爽感（给出一句话装懂胶囊）

小白爱上一个工具的核心爽点，是**读完立刻能用一句大白话向朋友复述出来**，彻底摆脱「看的时候热闹、合上书说不出」的无力感。

- 每篇转化稿都应自然凝练出一句 15–35 字的「白话复述锚点」（涵盖「遇到什么麻烦 → 做了什么动作 → 停在哪里」）。
- 需要极简卡片时，可通过 `bun run check-output -- <draft.md> --emit-beginner-card -` 导出**小白一秒读懂卡**。

## 二、卡点降维追问梯（当用户说「还是没懂」时）

如果用户读完标准折叠稿后反馈「还是有点绕」「没看懂」，严禁把原话换个词重说一遍，立即执行三级降维：

1. **从「多步流程」降维到「单步定格画面」**：暂时停下后续步骤，只把当前卡住的那一步变成眼前的慢动作（例如：「先不管后面怎么排序，只看眼前这一个人是怎么站定位置的」）。
2. **输出「小白一秒读懂卡」结构**：只给三样东西——「一句话大白话」「它到底防什么坑」「核心动作一对一」。
3. **配合苏格拉底微步（`references/socratic-microstep.md`）**：一次只问一个二选一的生活直觉问题（例如：「如果两扇门都从里面反锁了，屋里的人还能直接推开对方的门吗？」），等用户点头后再走下一步。
