# 记叙文表达（narrative）

当用户指定记叙文，或所讲机制天然是一段「有起因、有波折、有落定结果」的时间过程时使用。记叙文的精髓在于**「具体的人在具体的处境里做事、碰壁、再解决」**，而不是把说明书换上人称代词。

## 适合的机制

- 有明确先后顺序、状态流转或阶段推进的过程（如请求处理链路、拥塞控制、事务回滚）。
- 约束条件会在中途真实触发一次「拦截」或「转向」的机制。
- 起点和终点状态有鲜明对比，读者能直观看到变化结果。

## 写作要领

1. **处境开篇**：直接从一个具体的棘手处境或目标写起（为什么非做这件事不可？），不写空泛的议论帽。
2. **动作串起因果**：把机制的每一步转化为人物连贯的行动。前一步的结果自然推着他迈出下一步。
3. **受阻即约束**：当机制遇到边界或限制条件时，写成人物在现场撞上的具体阻碍（例如通道满了被迫退回、凭证对不上被拦在门外），让读者从这一次受阻中记住核心约束。
4. **干净收束**：事情办妥、状态落定后，用一两句平实的收尾点破这背后的运行规律。

## 禁区

- **严禁在正文里插入审稿式的括号批注**（如不在正文写「（此处为清单原因/环境暗示）」），所有结构核对留在内部折叠区。
- **不设机械的词汇计数配额**（无需生硬规定「全文只能出现一次情绪词」），但所有环境描写与人物反应都应服务于呈现机制张力，不写无病呻吟的煽情。
- 不编造原文没有的数字或违背机制的戏剧化巧合。
