# 论文导航

用于可读取的学术论文或 PDF。目标是先建立可靠、可追溯的理解，再解释**核心贡献**；不是逐页翻译，也不是把整篇论文压缩成一段故事。

## 默认范围

用户未指定范围时，解释「这篇论文解决什么问题、怎么做、为什么这个办法有用、边界是什么」。用户点名方法、图表、实验或结论时，以该部分为中心。

## 临时事实清单

按这个顺序读取，遇到关键缺口才扩展：

1. 题目：研究对象与主张的范围。
2. 摘要：问题、方法、主要结论。
3. 方法：输入、关键步骤、输出、约束与假设。
4. 结论：作者声称的贡献、局限或适用范围。

为每条用于解释的事实记录：事实 ID、简短主张、类型（原文事实 / 必要推导 / 尚未确认）、必要术语、映射术语、页码与章节锚点。理解用类比不要写进这份清单冒充论文主张。这个清单只属于当前会话的折叠分析或绝对临时评测目录；不能放入技能仓库、Git 记录或常规正文。读不清时按 `fact-traceability.md` 停写，不要编页码。

本地严格评测时，`evaluate-pdf` 只能生成带锚点的 `fact-ledger.draft.json`。经过人工或模型复核后，才在**绝对临时目录**建立 `fact-ledger.verified.json`；不可把抽取结果自动当作已验证事实。

```json
{
  "schema_version": "1.0",
  "review_status": "verified",
  "facts": [
    {
      "id": "F1",
      "claim": "经复核的机制主张",
      "required_terms": ["必要术语"],
      "mapping_terms": ["映射中的概念名"],
      "anchor": { "page": 1, "section": "abstract" }
    }
  ]
}
```

上面的对象是格式说明，不是可复用的论文答案。不要把任何具体论文的标题、术语或事实填进本文件。

## 不可靠时停止

- 文本层不可读、乱码严重或缺少关键页：说明不能可靠导航，请用户提供页码、截图或可复制文本。
- 抽取文本与页面视觉内容冲突：以页面内容为准，或暂停并说明冲突；不猜测。
- 用户要求逐页、逐句、全量改写：说明范围过大，请其指定章节或接受核心贡献版。不要把「全文较长」误当作「核心贡献不能解释」。

本地评测需要视觉交叉检查时，可让 `evaluate-pdf` 使用 `--render` 渲染关键页。它只提取和组织证据，不生成故事正文；正文仍须通过映射与门禁。

## 输出与映射

- 正常交稿只给转换稿、映射表和知识点校验；页码锚点仅在用户要求来源时，或保留在折叠分析中。
- 使用 `--facts <绝对临时路径/fact-ledger.verified.json>` 的严格本地评测时，映射表的第一列写成 `[F1] 概念`，知识点校验也写出 `[F1]`。这只是临时可追溯标记；普通知识解释仍使用描述性的概念名。
- 事实清单的每个必要术语必须出现在正文或知识点校验；每个映射术语必须出现在映射表的「知识概念」列；每个事实 ID 必须同时出现在映射表和知识点校验。任何一项缺失都不能宣称满分。
