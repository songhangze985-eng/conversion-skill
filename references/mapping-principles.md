# 通用映射原则

第 3 步卡住时读。一句话：**好的映射不是「看起来像」，而是「运作起来同构」。**

跨领域通用。形似只是入场券；神似、保真、粒度、约束可视才过关。示例写法见 `domain-examples.md`，不要把本文件的原则抄进 SKILL.md。

---

## 核心原则

### 1. 形似(表面相似)

**定义**:概念的**外在特征**与故事元素有**直观对应**。形似是"第一眼看上去就合理",降低读者的接受门槛。

**判别方法**:把概念和意象并排放在一起,问一句"这俩长得像吗?"——如果读者本能点头,形似就成立。

**示例**:
- "循环" → "反复检查"(都是重复动作)
- "分区" → "分两组站好"(都是按属性划分)
- "选举" → "举手投票"(都是表决)
- "递归" → "层层选拔"(都是自我嵌套)

**注意**:形似只是**入场券**,不是充分条件。只满足形似、不满足神似的映射,会落入"机制错配"陷阱(见下文)。

---

### 2. 神似(内在机制对应)——关键原则

**定义**:概念的**内在运作机制**必须与故事元素的**行为机制同构**。这是 5 条原则中最关键的一条。

**判别方法**:把概念的运作步骤和故事元素的行为步骤逐步对照,问两个问题:
1. 步骤数量是否一致?
2. 每一步的输入/输出/作用是否对应?

**经典示例**:贝叶斯更新 = 侦探改写怀疑度

| 贝叶斯机制 | 侦探行为 | 是否同构 |
|---|---|---|
| 拿到先验 $P(A)$ | 起手有一份初始怀疑度 | ✓ 输入对应 |
| 观测到证据 B | 看到现场脚印 | ✓ 触发对应 |
| 计算 $P(B\|A) \times P(A)$ | 评估"凶手留下这脚印的可能 × 原本怀疑度" | ✓ 运算对应 |
| 除以 $P(B)$ 归一化 | 扣除"别人也会留脚印"的干扰 | ✓ 修正对应 |
| 得到后验 $P(A\|B)$ | 改写嫌疑名单上的怀疑度 | ✓ 输出对应 |

机制完全同构,因此神似成立。

**反例**:把"贝叶斯更新"映射为"凶手自己招供"——虽然形似(都改变了对嫌疑人的判断),但机制完全不同(招供是单向陈述,没有"似然×先验÷边缘"的运算结构),神似不成立。

---

### 3. 保真优先

**定义**:当**形似**与**神似**冲突时,**神似优先**。宁可不那么"像",也不能扭曲知识机制。

**为什么必须如此**:转换skill 的根本目的是"让人懂知识",不是"讲个好故事"。故事是手段,知识是目的。如果为了故事顺滑而扭曲机制,读者记住的就是错误的知识,这比"没记住"更糟。

**冲突场景示例**:
- 概念:"递归必须有终止条件,否则无限循环"
- 形似意象:"永动机"
- 神似检查:永动机没有"终止条件"这一环节,机制不对应
- 保真处理:放弃"永动机"意象,改用"层层选拔直到没人可选拔"(选拔有终止,机制对应)

**保优先后的具体做法**:
1. 若某意象只能形似、不能神似,**直接弃用**,重新选意象。
2. 若某意象神似但形似弱,**可以保留**,但在故事中加强"机制说明"帮读者跨越理解门槛。
3. 若某意象会让机制变简单(如省略了归一化步骤),**必须补回**,哪怕故事会变啰嗦。

---

### 4. 粒度匹配

**定义**:**一个概念映射一个故事元素**,不要让一个角色 / 道具同时承载多个无关联概念。除非概念本身有从属关系(如"先验"是"概率更新"的子步骤),才可以合并。

**为什么必须如此**:一个角色塞多个概念,读者会混淆"这个角色现在到底在演什么",回溯校验时也无法对应。

**正例**(贝叶斯定理):
- $P(A)$ → 侦探的初始怀疑度(一个概念一个意象)
- $P(B|A)$ → 凶手留下脚印的可能(另一个概念另一个意象)
- $P(B)$ → 脚印总体常见度(又一个概念又一个意象)

**反例**:
- 把 $P(A)$、$P(B|A)$、$P(B)$ 全塞进"侦探的直觉"一个角色身上——读者无法分辨直觉到底对应哪个变量。

**例外(允许合并)**:若两个概念本身有从属关系,可以"父概念=角色,子概念=角色的某个动作/属性"。如"概率更新"是父概念,"先验"是其子步骤,可以让"贝叶斯酱"这个角色代表"概率更新"整体,而"初始怀疑度"是她的一个属性。

---

### 5. 约束可视

**定义**:把概念的**约束条件**(如 $P(B)>0$、终止条件、多数派门槛)转化为故事中的**规则 / 限制 / 门槛**,让约束也成为可见的故事元素。

**为什么必须如此**:约束条件往往是知识点的"边界",忽略约束会导致知识失真。把约束变成故事规则,既保真,又增加戏剧张力(规则=限制=冲突来源)。

**示例**:
- 贝叶斯约束 $P(B)>0$ → 故事规则:"证据必须确实出现,否则侦探无法推理"(没有脚印就没法更新怀疑度)
- 快排终止条件 → 故事规则:"一组里只剩一个人时,不用再比了,直接定名次"
- Raft 多数派约束 → 故事规则:"必须过半数议员举手,决议才算数"
- 免疫系统 MHC 限制 → 故事规则:"门卫只核对一类证件,证件类型不符直接拒绝"

**应用方法**:
1. 在第2步"提炼"中,显式列出所有约束。
2. 在第3步"意象映射"中,为每条约束找一个故事规则对应。
3. 在第4步"转换"中,让角色在剧情中"撞上"这些规则,而非旁白陈述。

## 选择意象的工作流(4 步)

为任意概念选择故事意象时,严格按以下 4 步走:

### 步骤 1:动词化——"这个概念在做什么动作?"

先把概念从名词转成动词短语,抓住它的"行为本质"。

| 概念(名词) | 动词化(它在做什么) |
|---|---|
| 贝叶斯更新 | 用新证据改写旧判断 |
| 快速排序 | 选基准、分两组、对两组重复 |
| Raft 共识 | 选领袖、抄作业、多数同意才算数 |
| 抗体免疫 | 识别外来物、记住特征、下次直接拦 |
| 导数 | 看某一瞬间的变化快慢 |
| OAuth2 | 拿临时通行证代替密码 |

> 若概念无法动词化(如纯定义性概念),退化为"它有什么属性",再为属性找意象。

### 步骤 2:候选意象——"现实里谁/什么会做类似动作?"

基于动词化结果,列举现实或二次元中会做类似动作的角色 / 场景 / 道具,至少列 2-3 个候选。

例(快排动词化="选基准、分两组、对两组重复"):
- 候选 A:校园运动会选拔赛(裁判选标准线,达标 / 不达标分两组,再分组比)
- 候选 B:超市结账分流(选一条队伍为基准,快的 / 慢的分两边)
- 候选 C:考试分班(选一个分数为基准,高的 / 低的分两班)

### 步骤 3:神似检查——"机制是否同构?"

对每个候选,逐步对照概念机制,看是否同构(参考原则2的判别方法)。

例(快排候选 A "校园运动会选拔赛"):
- 选 pivot(基准)→ 裁判定一条标准线 ✓
- 比pivot小的放左、大的放右 → 达标 / 不达标分两组 ✓(注:这里"小/大"对应"不达标/达标",方向可调)
- 递归处理两边 → 对两组再分别选拔 ✓
- 终止条件:组内只剩1人 → 选拔到只剩一人 ✓
- 机制完全同构,神似成立 ✓

例(快排候选 B "超市结账分流"):
- 选 pivot → 选一条队伍为基准(谁的基准?不确定) ✗ 机制模糊
- 分两边 → 快 / 慢分两边,但"快慢"是相对时间不是相对基准 ✗ 机制错配
- 神似不成立 ✗

→ 采用候选 A。

### 步骤 4:保真检查——"约束是否可嵌入?"

检查概念的约束条件能否自然嵌入候选意象的故事规则中。

例(快排候选 A 的保真检查):
- 约束:终止条件(组内≤1人)→ 故事规则:"一组只剩一人时不再比" ✓ 可嵌入
- 约束:pivot 本身不再参与递归(分区后 pivot 位置已定)→ 故事规则:"达标线一旦定下,定线的人这一轮就不比了" ✓ 可嵌入
- 约束:原地排序(可选特性)→ 故事规则较难体现,但这是实现细节非核心机制,可省略 ⚠️ 标注为非核心

→ 通过保真检查,采用候选 A。

## 跨领域映射示例表

下表给出 4 个领域的映射示例,演示上述原则的跨领域适用性:

| 知识领域 | 概念 | 形似意象 | 神似机制 | 约束可视化 |
|---|---|---|---|---|
| 数学(微积分) | 导数 | 赛车仪表盘瞬时速度 | 仪表盘读数 = 某一时刻的瞬时变化率,机制同构(取极限→读瞬时值) | 函数必须可导 → "赛道必须平滑,翻车处读不出速度" |
| 算法(排序) | 快速排序 | 校园运动会选拔赛 | 裁判定标准线→达标/不达标分组→对两组再选拔,机制同构(选pivot→分区→递归) | 终止条件组内≤1人 → "一组只剩一人就不比了" |
| 医学(免疫) | 抗体免疫 | 城门门卫识别通缉犯 | 门卫核对通缉令特征→认出就拦→把通缉令贴满城门记一辈子,机制同构(识别→清除→记忆) | MHC 限制 → "门卫只认一类证件,证件类型不符直接拒" |
| 架构(分布式) | Raft 共识 | 议会表决选议长 | 候选人拉票→过半数当选→议长发言所有人抄录→多数确认才生效,机制同构(选举→日志复制→多数提交) | 多数派门槛 → "必须过半数议员举手,决议才算数" |

> 这张表本身就是"通用映射原则"的最好证明:同一个方法论(形似+神似+保真+粒度+约束),可以无缝迁移到完全不同的领域。

## 常见陷阱

### 陷阱 1:过度类比(强行映射导致失真)

**表现**:为了用某个"很酷"的意象,强行把概念塞进去,导致机制被拉伸、扭曲、省略。

**典型例子**:
- 把"神经网络"映射成"大脑"——形似但神不似(人工神经网络≠生物神经网络,反向传播在生物中不存在),强行映射会让读者误以为"AI 真的像人脑"。
- 把"区块链"映射成"账本"——只抓住了"记录"这一面,丢失了"共识 + 不可篡改 + 密码学"的机制。

**规避方法**:每用一个意象,都过一遍"神似检查",任何一步机制对不上就弃用。

### 陷阱 2:机制错配(形似但神不似)

**表现**:意象看起来很像概念,但运作机制完全不同。读者会因为"像"而放松警惕,把错误机制当真。

**典型例子**:
- 把"哈希函数"映射成"把书放进书架"——形似(都是"放到某个位置"),但哈希是"输入任意长度输出固定长度",书架是"按属性分类摆放",机制完全不同。
- 把"死锁"映射成"两个人互相等对方先说话"——形似(都在等),但死锁的必要条件(互斥、持有并等待、不可剥夺、循环等待)一个都没体现。

**规避方法**:形似只是入场券,必须用"步骤逐一对照"确认神似(见原则2)。

### 陷阱 3:约束遗漏

**表现**:为了故事顺畅,省略了概念的约束条件,读者得到一个"看起来对、边界处错"的知识。

**典型例子**:
- 讲贝叶斯定理时不提 $P(B)>0$,读者遇到 $P(B)=0$ 的情形(证据根本不可能出现)就懵了。
- 讲快排时不提终止条件,读者以为"永远递归下去"。
- 讲 Raft 时不提多数派,读者以为"少数服从多数也行"。

**规避方法**:在第2步"提炼"中显式列出所有约束,在第3步为每条约束配一个故事规则,在第4步让角色"撞上"这些规则。

### 陷阱 4:粒度混淆

**表现**:一个角色承载多个无关概念,或一个概念被拆成多个角色,导致读者无法建立稳定的"概念↔意象"对应。

**规避方法**:坚持"一概念一意象",有从属关系的概念才允许"父角色+子属性"的合并(见原则4)。

### 陷阱 5:伏笔反噬知识点

**表现**:为制造反转,引入了与知识点无关的剧情,读者记住了反转却忘了知识点,或更糟——记住了错误的知识。

**规避方法**:反转点必须等于知识点的关键洞察。详见 `style-anime.md`。门禁失败先疑映射，再疑文笔。

映射过关后用 `style-anime.md` 演出来，再用 `lao-yu-gate.md` 检查外行听不听得懂。校验失败通常是本文件的神似或保真没过，回到第 3 步重选意象。
