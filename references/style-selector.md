# 表达风格选择指南

先完成「认知痛点梳理、事实清单与场景映射」，再决定用哪种文体讲出来。**风格只是帮读者看清机制的镜头角度，绝不能篡改概念关系、先后顺序或边界条件。**

## 选择优先级

1. **用户点名优先**：用户明确指定风格时，采用对应标识：`anime`、`detective`、`war-room`、`nature-documentary`、`verse`（现代短诗）、`narrative`（记叙文）、`podcast`（播客对谈）或 `neutral`（中性直述）。
2. **明确不要故事时走 `neutral`**：当用户说「正式一点」「别讲故事」「直接讲清楚原理」时，使用 `neutral`。`neutral` 同样需要在幕后完成映射与门禁，只是正文用干净利落的大白话和直观例子呈现。
3. **操作步骤类优先 `neutral` 或轻度类比**：涉及软件操作、命令配置等可执行步骤时，必须保留清晰的步骤清单，不要把操作指南写进闯关小说里。
4. **未指定时按机制特征匹配（默认 `anime` 标准档）**：若发现当前风格会让句子变得拧巴、拗口，立即切换为最顺畅的风格或 `neutral`。

## 各风格适配的机制形态

| 风格标识 | 最适合承载的机制形态 | 必读指南 | 核心底线（绝不能做的事） |
|---|---|---|---|
| `anime`（默认） | 规则分明、分工配合、递归循环、状态闯关 | `style-anime.md` | 禁止把术语硬译成尴尬人名或用中二黑话代替解释 |
| `detective` | 概率更新、故障排查、因果归因、真伪验证 | `style-detective.md` | 禁止跳过推理过程直接「灵光一闪破案」 |
| `war-room` | 分布式共识、并发调度、网络协议、主备容灾 | `style-war-room.md` | 禁止把去中心化/分布式协同写成「长官一句话全员照办」 |
| `nature-documentary` | 演化博弈、梯度下降、场域传播、宏观涌现 | `style-nature-documentary.md` | 禁止用「大自然很神奇」的抒情代替具体的传递与收敛规则 |
| `narrative` | 有清晰时间线、状态流转、中途触发拦截的过程 | `style-narrative.md` + `narrative-workflow.md` | 禁止在正文里插入破坏阅读的括号批注或编造虚假转折 |
| `podcast` | 容易引发直觉误区、适合层层追问「为什么」的机制 | `style-podcast.md` + `podcast-workflow.md` | 禁止写成一问一报菜名的审讯录，或堆砌无营养的寒暄 |
| `verse` | 循环迭代、精炼回环、一条铁律反复拦截的机制 | `style-verse.md` + `verse-workflow.md` | 禁止用生僻典故、倒装凑韵或漏掉关键终止条件 |
| `neutral` | 多维概念对比、严肃操作步骤、或任何套故事反而别扭的机制 | 无需额外风格文件 | 禁止退化回晦涩的教科书抄录 |

## 元信息标记

在内部完整稿标题下方固定保留两行元信息（供校验脚本识别，不计入读者正文）：

```markdown
> 表达风格：`anime`
> 篇幅：`default`
```
