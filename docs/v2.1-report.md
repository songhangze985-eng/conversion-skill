# conversion-skill v2.1 修改报告

日期：2026-09-17。工作树以 GitHub `origin/main`（`b679a54`，公开版本 2.0.0）为起点，在本地改到 2.1.0。没有 push、没有发 Release、没有改仓库名。

## 1. 修改前存在的问题

以同步后的 GitHub 仓库为准，不以分析文档里的历史 Python 树为准。当时本地旧副本落后于 `origin/main`。

产品定位仍把二次元写得很重，GitHub Description 还是「把晦涩专业知识通过四步流程转为二次元故事风格」，Topics 和 Homepage 为空。README 先讲流程和双语表格，缺少可核对的转换结果，安装只给了 Windows + Codex 的 `git clone`，没有验证过的 `npx skills add`。

核心工作流已经有事实清单、机制映射、风格包和知识点校验，但事实不分类，映射表没有适用边界，也没有可选的理解检验。`check-output` 用单一 `verdict` 覆盖结构与术语出现，容易被读成「知识正确」。评测目录只有行为规格，没有 A/B/C 对照框架。仓库没有 CONTRIBUTING、Changelog 和 Issue/PR 模板；Issue #1 仍未回复。

分析文档里「YAML 在 conversion / conversion-skill 之间晃」这件事，在当前 `main` 上已经不是事实：公开 YAML 就是 `conversion-skill`。skills.sh 的 404 仍然存在，属于外部目录站点。

## 2. 实际修改的文件及核心变更

保留了五步工作流、四种风格、论文页码锚点、作者情况回复，以及 `validate-input` / `generate-template` / `check-output` / `evaluate-pdf` 的原有 CLI。

- `SKILL.md`：版本 2.1.0；定位改为可验证解释；按需加载事实分类和理解检验。
- `README.md`：首屏改为定位、可核对快排样例和安装命令。
- `references/fact-traceability.md`、`references/comprehension-check.md`：新增。
- `references/mapping-principles.md`：补上输入/步骤/约束/输出四问和适用边界。
- `references/paper-navigation.md`、`references/domain-examples.md`、输出模板：与四列映射和事实分类对齐。
- `scripts/check-output.ts`：新增结构 / 术语覆盖 / 语义 / 理解四类结论；旧 JSON 字段和 `verdict` 含义保持为机械门禁。
- `scripts/generate-template.ts`：默认四列表；`--with-comprehension` 可选。
- `scripts/evaluate-pdf.ts`：评分卡写明结构 PASS 不能代替 8/8。
- `evals/`：协议、12 道公开题、输入原文、记录模板、机械检查夹具。
- `CONTRIBUTING.md`、`CHANGELOG.md`、`.github/` 模板、`docs/issue-1-reply-draft.md`。
